# Словарь данных

## Входные данные скоринга (`ScoringInput`)

Поля, передаваемые backend-ом в ML-сервис. Источник — анкета клиента, мок ФНС и мок БКИ.

| Поле                                | Тип              | Источник         | Описание                                                                                               |
|-------------------------------------|------------------|------------------|--------------------------------------------------------------------------------------------------------|
| `application_id`                    | строка / null    | Backend          | Идентификатор заявки для связи результатов. Не является признаком модели                               |
| `application_date`                  | дата (ISO)       | Backend          | Дата среза заявки — признаки вычисляются относительно неё                                              |
| `registration_date`                 | дата (ISO)       | Мок ФНС          | Дата регистрации компании — используется для расчёта возраста бизнеса                                  |
| `industry`                          | строка           | Мок ФНС          | Нормализованная категория деятельности: `retail`, `services`, `construction`, `manufacturing`, `other` |
| `product_type`                      | перечисление     | Клиент / backend | Тип кредита: `working_capital`, `equipment`                                                            |
| `revenue_6m_rub`                    | вещественное ≥ 0 | Клиент           | **Суммарная** выручка за 6 месяцев до заявки (не среднемесячная)                                       |
| `monthly_mandatory_expenses_rub`    | вещественное ≥ 0 | Клиент           | Обязательные ежемесячные расходы бизнеса                                                               |
| `has_active_loans`                  | булево           | Клиент + мок БКИ | Наличие действующих кредитов                                                                           |
| `existing_monthly_debt_payment_rub` | вещественное ≥ 0 | Клиент + мок БКИ | Ежемесячный платёж по действующим кредитам (0 если `has_active_loans = false`)                         |
| `past_overdue_count`                | целое ≥ 0        | Мок БКИ          | Количество прошлых просрочек платежей                                                                  |
| `requested_amount_rub`              | вещественное > 0 | Клиент           | Запрашиваемая сумма кредита                                                                            |
| `term_months`                       | целое 1–120      | Клиент           | Запрашиваемый срок. Лимиты продукта проверяет Decision Engine                                          |

**Не являются признаками модели:** ФИО клиента, телефон, ИНН, флаги согласий, текущий статус заявки, решения банка, будущие факты платежей. ИНН используется только как ключ для запроса в мок ФНС — передавать его в модель нельзя.

**Встроенная валидация (`ScoringInput`):**
- `registration_date` не может быть позже `application_date`
- Если `has_active_loans = false`, то `existing_monthly_debt_payment_rub` должно быть равно 0

## Производные признаки модели

Рассчитываются в `ml/features.py` из входных данных — единый источник для обучения и inference. Всего 15 признаков.

| Признак                                 | Тип            | Формула / логика                                                               |
|-----------------------------------------|----------------|--------------------------------------------------------------------------------|
| `industry`                              | категориальный | Из `ScoringInput.industry`; неизвестные значения нормализуются в `other`       |
| `product_type`                          | категориальный | Из `ScoringInput.product_type`                                                 |
| `company_age_months`                    | числовой       | Полных месяцев между `registration_date` и `application_date`                  |
| `avg_monthly_revenue_rub`               | числовой       | `revenue_6m_rub / 6`                                                           |
| `mandatory_expense_ratio`               | числовой       | `monthly_mandatory_expenses_rub / avg_monthly_revenue_rub`                     |
| `existing_payment_ratio`                | числовой       | `existing_monthly_debt_payment_rub / avg_monthly_revenue_rub`                  |
| `free_cashflow_rub`                     | числовой       | `avg_monthly_revenue_rub − expenses − existing_payment`                        |
| `has_active_loans`                      | бинарный       | `int(has_active_loans)` — 0 или 1                                              |
| `past_overdue_count`                    | числовой       | Напрямую из `ScoringInput.past_overdue_count`                                  |
| `requested_amount_rub`                  | числовой       | Напрямую из `ScoringInput.requested_amount_rub`                                |
| `term_months`                           | числовой       | Напрямую из `ScoringInput.term_months`                                         |
| `requested_payment_principal_proxy_rub` | числовой       | `requested_amount_rub / term_months` — только основной долг, **без процентов** |
| `payment_burden_ratio`                  | числовой       | `(existing_payment + principal_proxy) / avg_monthly_revenue_rub`               |
| `loan_to_revenue_6m_ratio`              | числовой       | `requested_amount_rub / revenue_6m_rub`                                        |
| `affordability_coverage_proxy`          | числовой       | `free_cashflow_rub / principal_proxy`, зажато в диапазоне [−10, 50]            |

> `requested_payment_principal_proxy_rub` — **приближение только для конструирования признаков**, не котируемый платёж. Для проверки платёжеспособности Decision Engine использует аннуитетную формулу с демо-ставкой из `policy.json`.

## Синтетический датасет для обучения

Генерируется скриптом `ml/generate_dataset.py`. Содержит те же поля, что и `ScoringInput`, плюс:

| Поле             | Тип    | Описание                                                                             |
|------------------|--------|--------------------------------------------------------------------------------------|
| `company_id`     | строка | Уникальный идентификатор компании. Каждая компания встречается только в одном сплите |
| `application_id` | строка | Идентификатор строки. Не подаётся в модель                                           |
| `default_12m`    | 0 / 1  | Целевая переменная: 1 = просрочка 90+ дней в течение 12 месяцев с выдачи (синтетика) |

**Важные ограничения датасета:**
- Представлены только кредиты, по которым известен исход (выданные). Отклонённые заявки не размечены нулём.
- Базовая доля дефолтов ~10% — настройка генератора, не реальный уровень банка.
- Даты разбиваются на train (до 01.01.2024), validation (H1 2024), test (H2 2024). Компании не пересекаются между сплитами.

## Ответ скоринга (`ScoringResult`)

| Поле               | Тип               | Описание                                                         |
|--------------------|-------------------|------------------------------------------------------------------|
| `application_id`   | строка/null       | Идентификатор из запроса                                         |
| `risk_level`       | `low/medium/high` | Класс риска по порогам из `models/metadata.json`                 |
| `predicted_pd_12m` | вещественное 0–1  | Синтетическая вероятность дефолта в течение 12 месяцев           |
| `risk_factors`     | массив            | Топ-4 влияющих признака с описанием и SHAP-вкладом (см. ниже)    |
| `model_version`    | строка            | Идентификатор версии модели из `metadata.json`                   |
| `scoring_backend`  | `"catboost"`      | Всегда `catboost` при работающей модели                          |
| `data_origin`      | строка            | `"synthetic_training"` — напоминание об учебном характере данных |
| `warning`          | строка            | Предупреждение о синтетическом характере оценки                  |

### Структура `risk_factors[]`

| Поле            | Тип                               | Описание                                                       |
|-----------------|-----------------------------------|----------------------------------------------------------------|
| `feature`       | строка                            | Название признака (из `FEATURE_COLUMNS`)                       |
| `description`   | строка                            | Читаемое описание на русском языке                             |
| `direction`     | `increases_risk / decreases_risk` | Направление влияния признака                                   |
| `shap_log_odds` | вещественное                      | SHAP-вклад в **логарифм шансов** (не изменение PD в процентах) |

> `risk_level = "low"` — классификация внутри синтетического симулятора. Не является реальным кредитным решением.

## Decision Engine (`decision/`)

### Вход — `VerificationData`

Формируется только backend-ом на основе результатов внутренних адаптеров. Не принимается от клиентского браузера.

| Поле                        | Тип          | Значения                                  |
|-----------------------------|--------------|-------------------------------------------|
| `company_status`            | перечисление | `active`, `inactive`, `unknown`           |
| `representative_authorized` | булево/null  | Подтверждены ли полномочия представителя  |
| `personal_data_consent`     | булево       | Согласие на обработку персональных данных |
| `credit_history_consent`    | булево       | Согласие на проверку кредитной истории    |
| `fns_check`                 | перечисление | `ok`, `pending`, `unavailable`            |
| `bki_check`                 | перечисление | `ok`, `pending`, `unavailable`            |

### Выход — `DecisionResult`

| Поле                             | Тип     | Описание                                                                    |
|----------------------------------|---------|-----------------------------------------------------------------------------|
| `recommendation`                 | строка  | `approve`, `alternative_offer`, `needs_info`, `manual_review`, `reject`     |
| `reason_codes`                   | массив  | Машиночитаемые коды причин                                                  |
| `explanation`                    | строка  | Человекочитаемое объяснение                                                 |
| `offer`                          | объект  | Сумма, срок, **демо-ставка**, расчётный аннуитетный платёж (если применимо) |
| `missing_items`                  | массив  | Что не хватает для продолжения рассмотрения                                 |
| `policy_version`                 | строка  | Версия `policy.json`                                                        |
| `scoring_model_version`          | строка  | Версия ML-модели                                                            |
| `requires_employee_confirmation` | `true`  | Всегда: предварительная рекомендация, не финальное решение                  |
| `finalized`                      | `false` | Всегда: статус заявки меняет только backend через Workflow                  |

### Валидация решения сотрудника — `ValidatedStaffAction`

Результат `StaffActionValidator.validate()`. **Не сохраняет** изменений в БД и не меняет статус заявки — это делает backend в своей транзакции.

| Поле                   | Тип    | Описание                                                              |
|------------------------|--------|-----------------------------------------------------------------------|
| `validated_only`       | `true` | Всегда: объект ещё не сохранён                                        |
| `persistence_required` | `true` | Backend обязан сохранить действие сам                                 |
| `action`               | строка | `approve`, `alternative_offer`, `reject`, `request_info`              |
| `offered_amount_rub`   | число  | Предложенная сумма (в рамках лимитов продукта)                        |
| `offered_term_months`  | число  | Предложенный срок                                                     |
| `reason`               | строка | Обязателен при `reject`, `request_info` и ручном одобрении HIGH-риска |
